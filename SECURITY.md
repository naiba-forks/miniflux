# Security Policy

## Supported Versions

Only the **latest stable release** receives security fixes.

Before reporting, please check that the issue still happens on the latest version.

## Reporting a Vulnerability

For vulnerabilities in **upstream Miniflux** code, use the upstream **[GitHub Security Advisories](https://github.com/miniflux/v2/security/advisories/new)**. Upstream only accepts reports through GitHub Security Advisories.

For vulnerabilities specific to **MinifluxNg fork features** (AI summary, web scraper, Obscura), [report privately via GitHub](https://github.com/naiba-forks/miniflux/security/advisories/new) or email `hi@nai.ba`.

If you are not familiar with private reporting, read the [GitHub documentation](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability).

Do not post vulnerabilities in public issues, pull requests, or discussions.

## What to Include

- Affected version and configuration
- Description of the issue and its impact
- Steps to reproduce, or a proof of concept

Keep your report short and to the point, and verify the issue yourself before submitting it. Please do not submit long, AI-generated reports.

Reports that are vague, speculative, or that cannot be reproduced will be closed without further discussion.
